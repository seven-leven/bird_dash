# Use the platform

> **Status:** planned 2026-10-27; phases 1 to 3 done 2026-10-27, phase 4 and the rows that waited
> for the site overhaul on 2026-10-28. Left: popovers and accessibility checks, which need the test
> overhaul's real browser (its phase 7), and offline, which needs versioned images. What Node 24,
> TypeScript 6, Vite 8, Vue 3.5, Tailwind 4 and the browser already give this project that it does
> not use yet, and the architectural and general improvements found in the same look. Much of it
> rode along with the test and site code overhauls (the site's is done, 2026-10-28; see the
> CHANGELOG); the rest is small and stands alone. Delete this page when every row is done or
> dropped.

## Why

The stack is current, but the code was written a piece at a time, and several pieces are written by
hand where the platform has one built in: a viewer that traps focus itself, a dropdown that watches
for clicks outside, two argument parsers, `try`/`finally` around every fake in the tests. Each
built-in that replaces one removes code, and usually fixes an edge the hand-written one missed. The
same look turned up two bugs (the colour scheme, the month names) and a handful of gaps that are not
about the stack at all (the data is trusted unchecked, an error leaves a blank page, nothing
measures size or accessibility automatically).

## The rule

**Prefer the platform.** A built-in comes before hand-written code, and hand-written code comes
before a dependency. Each row below has to remove code, fix something, or make something visible to
a visitor better; a feature used only because it is new is not a reason. Recorded in DECISIONS.md
with phase 1.

## Beyond the stack

Architectural and general improvements found in the same look. Each one is a pull request of its
own, at the point given.

| Improvement                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | When                                                                                                                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Semantic colour tokens with `light-dark()`.** 125 `dark:` classes in the `.vue` files pair a light and a dark value by hand (`bg-white dark:bg-slate-900`). Once `color-scheme` is set, `tokens.css` can define `--surface`, `--ink`, `--muted`, `--rule` and the tile grey once each with `light-dark()`, exposed through `@theme` as `bg-surface`, `text-ink`, …; most `dark:` classes go. | **Check the data at the door.** `fetchJson` returns `res.json() as T`: a list with a missing field or a wrong type reaches a component and fails there, far from the cause. A small hand-written guard per file shape in `data/files.ts` (no dependency) turns a malformed file into the page's error state with the file and the field named; the data contract test uses the same guards on the committed files.                                                                       | ✓ 2026-10-28                                                                                                                                                    |
| **An error state for the whole app.** A component that throws leaves a blank page. `app.config.errorHandler` (and `onErrorCaptured` in the shell) shows an error state with "Try again", like the one the loaders already have ("Couldn't load the gallery").                                                                                                                                                                                                                            | ✓ 2026-10-28, with `ui/ErrorBoundary` (below)                                                                                                                   |

| **A size budget.** ✓ The site's build measures what a visitor downloads (the JavaScript and CSS gzipped, the largest full drawing and thumbnail) and fails over the limits in `script/build/sizeBudget.ts`, a Vite plugin, so every `vite build` checks it, CI included. ## Not in this plan

- **A state library, a router or a UI kit.** The stores, `defineInjection` and the hash route are
  small and tested; a library would add more than it removes.
- **Server rendering or a static site generator for the gallery.** It is one page over JSON; the
  link previews above get the one thing SSR would.
- **The History API instead of the hash.** GitHub Pages has no fallback to `index.html` for unknown
  paths, so a deep link would 404; the hash stays (DECISIONS.md).
