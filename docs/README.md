# Documentation

Reference pages describe how the project is today and are kept true as the code changes. Plans
describe work that has not happened yet; each one is deleted (or folded into a reference page) once
it is done.

## Reference

| Page                                     | Read it when                                                           |
| ---------------------------------------- | ---------------------------------------------------------------------- |
| [ARCHITECTURE.md](ARCHITECTURE.md)       | You need the big picture: the three programs, the site's layers, rules |
| [DATA.md](DATA.md)                       | You add a drawing or a collection, or change a field in `public/`      |
| [DESIGN.md](DESIGN.md)                   | You add a button, a colour or an icon                                  |
| [TESTING.md](TESTING.md)                 | You write a test or want to know what the tiers and areas mean         |
| [TEST-PROCEDURES.md](TEST-PROCEDURES.md) | You set up a machine, a test or CI fails, or you maintain the runner   |

## Assets

[`assets/`](assets/) holds generated images: the design guide, the icon sheet, the logo sheet and
the logo files. Do not edit them by hand; `npm run design` redraws them from the code
([`script/design/draw_design_guide.ts`](../script/design/draw_design_guide.ts)), and a contract test
fails when they are out of date.

## Adding a page

- Describes how something works now → top level, and add it to the table above and to the
  [README](../README.md#documentation).
- Describes work to do → `plans/`, with its status in the first lines.
- An image → `assets/`, preferably generated by a script so it cannot drift.
